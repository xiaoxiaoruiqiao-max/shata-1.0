# 沙塔1.0 · 应用说明


四只 ETF 的 25 日加权动量信号、历史模拟和独立的 50 万元实盘账本。规则全文见页面的「实盘试验」。网页不接券商接口，成交、异常和权益变动由用户按券商回报登记。

## 本地使用

需要 Python 3.10 或以上，无第三方依赖。

    python dashboard.py serve --port 8765

打开 http://127.0.0.1:8765 。在首次实盘交易日，由账户为空仓时登记「启动试验」。当日实际成交按北京时间和先后顺序登记，买卖手续费填写券商实际费用。09:35 同侧报价指卖出用买一、买入用卖一。纳指买入另记当时券商显示的有效参考净值。错误可撤回最后一条后重录。建议定期下载账本，并留存券商交割单。

    python dashboard.py refresh
    python dashboard.py check
    python -m unittest -v test_pilot
    python -m unittest -v test_shadow

`refresh` 立即核对行情。`check` 校验历史汇总。测试使用既有日线和独立测试账户。

## 账本口径

- 历史模拟保留 3,365 个交易日底稿和 2013 年上市前的代理行情，沿用次日开盘、单边万二，后续日线沿用历史模拟口径。实盘曲线、持仓日历、月度和年度统计从试验起始日开始，采用券商确认的成交和收盘行情。
- 实盘试验以人民币 50 万元现金开账，试验期不加入资金。卖出实现收益按移动平均成本扣实际费用，现金分红在券商到账后单独登记，份额调整应先与券商核对后补录。请及时补录，漏录权益变动会影响收盘估值和止线判断。盘中成交登记后，净值待下一次收盘核对。
- 同池等权对照以试验开始日的开盘价模拟初次建仓，之后每月首个四只 ETF 均有开盘数据的交易日开盘再平衡，使用复权行情，双向成交均按单边万二。年化收益在实盘满 365 天后显示。实盘止线从收盘净值高点计算。
- 3% 溢价、15% 试验止线和加仓门槛是本次试验规则。未成交或临时停牌由券商确认，看到提示后在券商界面人工处理。通过加仓审查只意味着可以复核，账本不会自动追加本金。

## 数据更新

- 北京时间每天 18:15 核对收盘，18:35、19:05、次日 08:15、08:45 补采。进程启动时立即核对。服务端不依赖用户打开网页。
- 新浪和腾讯对比开收盘，东方财富用于权益事件和同日收盘溢价参考；上交所用于休市日历。交易日不明、双源行情缺失或不一致时暂停新买入提示，保留最近完整快照。
- 如基金经交易所公告确认全天停牌，且两路行情均无记录，维护者可在状态目录添加 `confirmed_halts.json`，例如 `{"2026-11-16":{"sh513100":"公告链接"}}`，再执行 `refresh`。示例日期仅用于示范格式。盘中临停仍以券商及公告为准。
- 当前日线来源无法提供 09:35 实时报价和有效参考净值。请在券商内核对并填入看板。看板执行检查仅计算价格门槛，不会提交或撤销订单。

## 两版并行模拟

- 独立的两本模拟账各从 50 万元现金起跑。上证180版沿用原池，红利版仅替换第四只为 510880。部署时确定前瞻起始日，之前的 26 个红利 ETF 收盘日仅供计算动量。实盘账本仍按券商回报单独登记。
- 北京时间 09:35–09:49，每分钟采集一次腾讯与新浪盘口，用买一卖一、报价时间、可见对手盘数量和涨跌停价格核对。盘口和有效 IOPV 不足时保留原仓。以 09:35 报价固定保护价，之后每分钟最多尝试一单，先卖完再买，纳指买入每次都重新核对 3% 门槛。取公开可见数量作为成交上限，不能确认真实排队顺序。
- 北京时间 18:17 独立结算，18:37、19:07、次日 08:20 和 08:47 补采或复核。收盘核对未齐时，两版均等待，停机错过的窗口只补记估值与跳过原因，不补造盘中成交。
- 模拟手续费统一单边万二，分红除息日计应收、发放日可用。各自的 15% 收盘止线触发后只尝试退出，保留后续估值和日志。使用持久化状态目录中的 `shadow.json` 保存起始日、采集窗口和两本账。

## 双版历史动量看板

- 两版历史从 2013-09-02 起使用实际 ETF 交易行情，全部基金先积累 25 个交易日作为初始信号。原始快照覆盖至 2026-11-13，之后随原组合和 510880 的双源数据续算，统一使用前收盘排名、次日开盘及单边万二。日线模拟不含盘中执行限制或 15% 止线。
- 共用八个观察区间，以最近共同核对的交易日向前按日历月取整，区间首个交易日前的收盘净值作为起算基准。图表和卡片以该基准重算累计收益与最大回撤。
- 历史底稿 `data/dual_history.csv` 随部署包分发。实盘和前瞻模拟均有独立账本，历史区间筛选不会改动任何账本。
- 「动量轨迹」绘制同一交易日的原始 25 日加权动量分数，分别显示原版和红利版的四只 ETF。近 15 天取最近 15 个共同交易日，月与年区间按日历月回推。历史分数底稿为 `data/momentum_history.csv`，随后和双版收盘更新一起追加。
- 「持仓日历」的历史模式把上证180版和红利版并列，共用年月与选中日期。上证180版沿用原始历史底稿，红利版从 2013-09-02 起使用双版历史底稿；两边显示各自的日度及月度组合收益。切换为实盘模式时显示实际账本的持仓日历。

## 云服务器部署

建议用 Docker Compose 持续运行，在本目录执行：

    docker compose up -d --build
    docker compose logs dashboard
    curl -fsS http://127.0.0.1:8765/api/dashboard -o /dev/null

Compose 将网页端口绑定到服务器回环地址。使用 SSH 隧道私下访问，客户端执行：

    ssh -N -L 8765:127.0.0.1:8765 用户名@服务器

打开本机 http://127.0.0.1:8765 。如需域名，反向代理整个网站（包括 `/api`）并启用 HTTPS 与访问认证，保留原请求的 Host。网页没有账号系统，请保持端口不对公网开放。服务器需允许出站 HTTPS 访问新浪、腾讯、东方财富和上交所。

Docker 使用 `etf-state` 持久化卷。备份卷中的 `pilot.json`、`shadow.json`、`state.json` 和更新后的休市日历。使用裸机 Python 时，以 systemd 或现有守护进程运行，并将 `ETF_STATE_DIR` 指向可写的持久目录。进程关闭期间不采集；正常重启会尝试补齐遗漏交易日。
